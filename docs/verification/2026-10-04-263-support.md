Jade tooltip fixes for 26.3 (CeJadePlugin)
- The raw CraftEngine id line ("CraftEngine: <id>") is now gated behind
  BlockAccessor#showDetails() - Jade's own details mode, bound to Left Shift
  (InputConstants.KEY_LSHIFT = 225, which is what Jade registers for key.jade.show_details).
- The bottom mod-name line (JadeIds.CORE_MOD_NAME, which Jade resolves from the vanilla carrier
  block/item and therefore rendered as "Minecraft") is replaced with the CraftEngine id's
  namespace, keeping Jade's mod-name styling.
- Jade's carrier-only lines are removed for CraftEngine blocks (JadeIds.MC_NOTE_BLOCK: the
  "Snare Drum F" instrument/note line of the note block CraftEngine blocks are disguised as).
- Evidence (Paper 26.3 + CraftEngine 26.9.2 + Jade 26.3.5, block genemachinery:electric_furnace
  placed with /ce debug setblock 104 -60 86 genemachinery:electric_furnace):
  - _server263/shots-cebridge/jade-263-final.png  -> tooltip is "电炉" + "genemachinery" only
    (no "Snare Drum F", no id line)
  - _server263/shots-cebridge/jade-263-forced.png -> with the details gate temporarily forced on
    (throwaway build, reverted), the tooltip renders "电炉" + "CraftEngine:
    genemachinery:electric_furnace" + "genemachinery", proving the details-mode render path.
  - The details gate itself could not be triggered by injected keys: this client ignores
    PostMessage key events while its window is unfocused (verified: an injected "E" no longer
    opens the inventory), so the Shift-held frame was produced with the gate forced instead.
